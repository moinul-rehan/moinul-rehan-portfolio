How I Work

From a messy brief to something users trust.

Discover

Understand before designing anything.

Every project starts with questions, not screens. I sit with stakeholders, map the real workflow, and figure out what's actually broken before opening Figma.

  • Stakeholder interviews
  • Mapping the current workflow
  • Defining what success looks like
Design

Explore wide, then commit.

Low-fidelity flows first, then high-fidelity screens once the structure is agreed. Nothing goes to prototype until the layout has earned it.

  • Wireframes and flows
  • Visual design system
  • Internal review loops
Prototype

Make it feel real before it's built.

Interactive prototypes so stakeholders and users react to something real, not a static mockup. It's cheaper to change a prototype than a codebase.

  • Clickable Figma prototypes
  • Usability walkthroughs
  • Edge cases caught early
Deliver

Handoff that doesn't lose the details.

Specs, redlines, and a design system devs can actually build from — plus staying involved through implementation so nothing gets lost in translation.

  • Dev handoff docs
  • Design QA on build
  • Post-launch iteration
